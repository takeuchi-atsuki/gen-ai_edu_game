# 企画書A：ことばの弟子（仮）

作成日：2026-10-23／状態：企画初稿・未検証

[3案の比較と共通方針](README.md)

## 1. 企画の要約

プレイヤーはAIの教育係となり、限られた授業で話し方や価値観を育て、討論大会の優勝を目指す。正論、共感、質問などを組み合わせ、相手と会場の審査基準に合わせて教え方を変える、短時間周回型の育成ゲーム。

**訴求文：あなたが教えた口癖が、必殺技にも弱点にもなる。**

| 項目 | 仮の方針 |
| --- | --- |
| ジャンル | AI育成・討論戦術・周回型シングルプレイ |
| 販売先・対象環境 | Steam／Windows PC／日本語 |
| 1周の長さ | 30〜45分 |
| 育成期限 | 教育12回、公式戦3回で1周終了 |
| 価格案 | 買い切り980円。購入意向と完成度を見て再検討 |
| 通信 | 基本プレイはオフライン完結 |
| 最優先の面白さ | 自分の教えが会話と勝敗に表れ、次の教育方針を考えたくなること |

想定するプレイヤーは、短い育成ゲーム、性格の違うキャラクター、デッキや技能の組み合わせが好きな人。実際の長文討論や自由なAIチャットを主目的とする人とは期待を分ける。

## 2. プレイヤー体験

「間違っていても引くな」と教えると、強く主張できる一方、誤りの訂正が苦手になる。「相手の話を聞け」と教えると、共感を得る一方、攻める機会を逃しやすくなる。

同じ能力値でも、教えた技と性格の組み合わせで戦い方が変わる。単なる攻撃力の大小ではなく、教育の偏りと相手との相性を攻略の対象にする。

短いプレイ例：

1. 次の相手は挑発が得意、会場は「根拠」と「礼節」を重視すると分かる。
2. 残り2回の授業で、反論力を伸ばすか、挑発に乗らない訓練をするか選ぶ。
3. 試合でAIが挑発を受け流し、教えた「確認の質問」を使う。
4. 結果画面に、授業→覚えた技→採点への効果が表示される。

## 3. 基本ループと勝敗

`初期方針を選ぶ → 教育4回 → 公式戦 → 教育4回 → 公式戦 → 教育4回 → 決勝 → 修了記録`

- 最初の2試合は勝敗にかかわらず次へ進み、相手の違いを学べる。勝利時は追加の教育選択肢を得るが、能力への無制限な加算はない。
- 決勝に勝てば大会優勝。負けても修了記録を残し、次周へ進める。
- 全3試合の成績は称号に反映する。初戦敗北だけで、その周の優勝が不可能になる設計は避ける。
- 次の相手と審査軸は、その区間の育成前に公開する。対策する機会のない相性事故を抑える。

## 4. 教育と成長

| 要素 | 遊びでの役割 |
| --- | --- |
| 論理 | 根拠を使う技、矛盾への反論を強める |
| 共感 | 相手の主張を受け止める技、観客への訴えを強める |
| 観察 | 相手の狙いや弱点を見抜く |
| 胆力 | 挑発や劣勢による動揺を抑える |
| 性格 | 技の選びやすさや追加効果を変える。長所と短所をセットにする |
| 集中 | 強い教育の連続を制約する。休息も教育1回を消費する |

教育は、例題への返答を選んで教える「指導」、能力と技を伸ばす「演習」、集中を戻す「休息」から選ぶ。最小試作では合計6種類の選択肢に絞る。

能力は初期仕様では0〜100の範囲とし、上限に達しなくても12回の教育で終了する。強い技にも準備条件や弱点を置く。覚えた技から持ち込めるのは4つまでとし、何でもできる構成を防ぐ。

育成結果を評価する際は、「高い数値になったか」だけでなく「相手に合わせて技と性格を組めたか」を重視する。

## 5. 討論バトルの仕組み

1試合は仮に4ラウンド、2〜3分。各ラウンドで双方が1つずつ会話技を選び、ルールに従って解決する。AIは事前に組んだ作戦と性格から技を選ぶ。プレイヤーは1試合2回だけ、候補として表示された技に切り替える助言ができる。

| 技の系統 | 例 | 強みと制約 |
| --- | --- | --- |
| 主張 | 結論を言い切る | 点を得やすいが、根拠不足だと反論される |
| 根拠 | 具体例を示す | 次の主張を補強するが、準備に1手使う |
| 質問 | 前提を確かめる | 相手の準備を崩すが、質問だけでは点を伸ばせない |
| 共感 | 心配を受け止める | 共感重視の会場で強く、論理重視では効率が落ちる |
| 反論 | 矛盾を指摘する | 条件が合うと強いが、相手が根拠を整えていると不発になる |

採点は「技の基礎点＋準備や相性の補正＋審査軸の補正」で構成し、内訳を見せる。最小試作では命中率等の乱数を入れず、選択と結果の関係を確認する。合計点が高い側の勝利、同点は引き分けとし、決勝の引き分けは優勝なしの特別修了とする。

議題は「町の祭りは夜に開催すべきか」など、前提情報をゲーム内で読める架空の題材を使う。議題ごとの事実カードと技の対応から発言を組み立て、プレイヤーの現実の知識量に依存させない。

**自由文をLLMに審判させて勝敗を決める仕様は初期版に含めない。** 技に対応する短いセリフと採点理由を表示し、セリフの面白さとゲーム上の判定を両立する。

## 6. AI・プロンプトの役割

- 最小試作：初期方針を選択式で指定し、教育で行動の重みや技構成が変わる。発言は議題・性格・技に対応するテンプレートで生成する。
- 発売候補：入力した短い教育方針を、対応する性格タグへ変換する機能。ただし、解釈結果を先に表示し、修正できるようにする。実装費用に見合うか検証してから採否を決める。
- 将来のLLM用途：既に決まった技の意味を変えずに、口調や言い回しを変える。出力失敗時はテンプレートに戻す。能力値・技の効果・採点はモデルに変更させない。
- ローカルLLMの同梱や外部APIは必須にしない。使わなくても全試合を遊べる構成を保つ。

ストアでは「育成で話し方や戦術が変わる」と説明する。自由な会話や、実際のモデル再学習を実装していない段階で、それらを提供するように見せない。

## 7. 周回と成長の上限

教育12回、装備技4枠、能力上限で成長を制限する。試合をやり直して報酬を積み増す仕組みは設けない。

周回では、新しい初期方針、技、対戦相手の組み合わせを解放する。前周の能力値は引き継がない。AIの名前、口癖、最も効果があった授業、成績は修了アルバムに残す。

再プレイの動機は、異なる性格での優勝、苦手な審査基準への対応、珍しい技の組み合わせを発見することに置く。

## 8. 最小試作と発売候補の範囲

| 項目 | 最小試作 | 検証後の発売候補 |
| --- | --- | --- |
| 進行 | 教育4回＋1試合 | 教育12回＋3試合の1周 |
| 初期方針 | 2種 | 3種 |
| 教育 | 6種 | 10種 |
| 技 | 6種、装備4枠 | 12種、装備4枠 |
| 相手 | 1体 | 6体から1周3体を選出 |
| 議題 | 1題 | 6題 |
| 審査軸 | 2種類の評価設定 | 3種類の評価設定 |
| 画面 | 教育、作戦、試合、結果 | 左記にタイトル、説明、セーブ、修了アルバムを追加 |

発売候補の数量は、制作時間と重複感を確認して調整する。オンライン対戦、自由チャット、音声会話、長編ストーリー、モデルの再学習は対象外。

仮素材でも技と採点を読めることを優先する。発言は1回2文程度を目安にし、早送りと履歴確認を用意する。

## 9. 技術方針と品質確認

2DのUI中心に構成し、Godot等のPC向けエンジンを候補とする。採点処理、AIの技選択、セリフ表示を分離する。技・教育・議題はデータとして定義し、数値調整でルールを追えるようにする。採用エンジンは未決定。

確認する内容は、同じ入力で同じ点になること、採点表示と内部計算の一致、授業の効果が作戦へ反映されること、保存後に育成回数が増減しないこと。代表的な技の組み合わせについて、常に有利な一択がないかをプレイと小規模な対戦シミュレーションで調べる。

## 10. 収益と販売の仮説

定価980円、平均受取率60%、月の運営費2,000円という共通仮定では、月21本で月次運営利益10,348円。開発人件費・初期費用回収を含まない試算である。[共通の利益定義と計算](README.md#月1万円の利益に向けた共通試算)を参照。

見せたい映像は「教育方針を選ぶ→AIがその癖を出す→勝敗理由が分かる」の一続き。体験版は教育4回と1試合を含め、終了時に別の育成方法で再挑戦できるようにする。文章の量より、教えたことが変化として見える場面を訴求する。

近い育成・会話・戦術ゲームの価格とレビューを確認し、「会話を読む楽しさ」と「勝敗を攻略する楽しさ」のどちらに購入意向があるかを調べる。販売見込みは未算定。

## 11. 検証計画と判断基準

最初は紙や表で1試合を再現し、採点に矛盾がないことを確認する。その後、仮素材で最小試作を作り、想定プレイヤー5人程度に遊んでもらう。

| 仮説 | 観察すること | 次段階へ進む仮基準 |
| --- | --- | --- |
| 教育が勝敗と結びつく | 終了後に、どの教育が何に効いたかを説明できるか | 5人中4人以上が具体例を1つ説明できる |
| 次の育成を考えたくなる | 2回目に自分で教育や技構成を変えるか | 5人中3人以上が自発的に変更して再挑戦する |
| 討論の採点に納得できる | 結果を見て勝敗理由を説明できるか | 5人中4人以上が結果表示だけで説明できる |

この人数と基準は早期の観察用で、統計的な販売予測ではない。採点の説明を改善しても納得されない場合は、議題と技の種類を減らして再検証する。自由な会話への期待と実際の遊びが合わない場合は、LLM追加の前に訴求とルールを見直す。

## 12. 主なリスクと次の成果物

| リスク | 対応方針 |
| --- | --- |
| 会話の内容と採点が合わない | 技の意味を先に確定し、その意味に沿うセリフを表示する |
| 文章が長く試合が止まる | 発言を短くし、履歴と早送りで読む速さを選べるようにする |
| 特定の教育だけが強い | 相手と審査軸を変え、対策可能な弱点を持たせる |
| 育成AIという印象が弱い | 教育前後の発言・選択の違いを結果画面で見せる |

次に作るのは「教育6種・技6種の一覧」「1試合の採点例」「4画面のラフ」。これらで最小試作を具体化し、発売範囲の拡大はプレイテストの後に判断する。
