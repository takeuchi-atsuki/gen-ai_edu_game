# 企画書B：迷宮の教え子（仮）

作成日：2026-10-23／状態：企画初稿・未検証

[3案の比較と共通方針](README.md)

## 1. 企画の要約

プレイヤーは探索用AIの教育係となり、危険の避け方、報酬の選び方、敵との戦い方を教える。AIは教わった方針で迷宮を探索し、帰還後に行動記録を見ながら教育を改善する。限られた3回の遠征で、最後の迷宮の守護者を突破する育成・探索ゲーム。

**訴求文：前回の失敗を教え直して、今度こそ自分で帰っておいで。**

| 項目 | 仮の方針 |
| --- | --- |
| ジャンル | AI教育・探索戦術・周回型シングルプレイ |
| 販売先・対象環境 | Steam／Windows PC／日本語 |
| 1周の長さ | 45〜60分 |
| 育成期限 | 教育9回、探索3回で1周終了 |
| 価格案 | 買い切り1,280円。購入意向と完成度を見て再検討 |
| 通信 | 基本プレイはオフライン完結 |
| 最優先の面白さ | AIの判断の理由を理解し、少し教え直すと行動と成果が変わること |

想定するプレイヤーは、ローグライト、行動の自動化、準備で勝つゲームが好きな人。複雑なプログラミングを前提にせず、条件と行動をカードとして選べるようにする。

## 2. プレイヤー体験

宝箱を優先するように教えたAIが、回復を後回しにして危険な道へ進む。帰還後、「体力が少ないときは回復を優先」を追加すると、次の探索では自分で立て直す。しかし、そのルールに枠を使ったため、別の敵への対処は単純になる。

面白さは、完璧な万能AIを作ることより、次の迷宮に合った判断を少ない教えで実現することに置く。

短いプレイ例：

1. 次の迷宮には罠が多いと事前に分かる。
2. 「宝箱優先」を外して「罠の兆候があれば安全な道」を教える。
3. AIが分岐で安全な道を選び、画面に判断に使った教えが表示される。
4. 帰還記録から、回避した危険と逃した報酬を見て、方針の良し悪しを考える。

## 3. 基本ループと勝敗

`初期性格を選ぶ → 教育3回 → 探索 → 教育3回 → 探索 → 教育3回 → 最終探索 → 卒業記録`

- 探索ごとに迷宮の傾向と守護者の特徴を予告し、教育の材料にする。
- 各探索は8段階の進行を上限とする。途中で2つ程度の候補から進路を選び、最後の段階に出口または守護者を置く。
- AIが進路や戦闘行動を決める。プレイヤーは各探索2回まで、候補の進路または行動を指定できる。
- 体力が尽きるか自主撤退すると、その探索は終了する。教育と探索の残り回数は戻らず、同じ探索を繰り返して報酬を稼げない。
- 最初の2回で失敗しても次へ進める。最低限の教育機会は保証し、報酬不足だけで操作不能にならないようにする。
- 3回目で守護者を倒して帰還すれば卒業成功。それ以外も記録を残してその周を終える。

## 4. 教育と成長

| 要素 | 遊びでの役割 |
| --- | --- |
| 体力 | 危険な道や連戦に耐える |
| 攻撃 | 戦闘を短く終わらせる |
| 観察 | 罠や相手の兆候を見つける |
| 行動エネルギー | 強い技、偵察、回復行動に使う探索中の資源 |
| 性格 | 教えが当てはまらない場合の基本判断を変える |
| 判断ルール | 状況と行動を結びつける。最大4枠で優先順位を持つ |

教育1回では、「状況の例を見る→望ましい行動を選ぶ→演習で結果を確かめる」を行う。新しいルールを教えるか、既存のルールを調整しながら関連能力を伸ばすかを選ぶ。探索報酬の学習素材は、残りの教育を強化するために使い、追加の教育回数には変換しない。

能力の範囲は初期仕様では0〜100とし、探索中の体力・エネルギーとは区別して表示する。装備による強化は2枠まで。成長を説明する軸を増やしすぎない。

## 5. 判断ルールと探索の仕組み

判断ルールは「条件→行動」のカードで作る。複数の条件が一致した場合は上のルールを優先し、実行できない行動は理由を表示して次の候補へ進む。どれも使えない場合は性格ごとの基本行動を使い、停止しないようにする。

| 教えの例 | 行動の変化 | トレードオフ |
| --- | --- | --- |
| 体力が低い→回復を優先 | 回復手段があれば使う。なければ安全な候補を選ぶ | 報酬効率や攻撃機会が落ちる |
| 罠の兆候→偵察する | 資源を使って危険を確認する | エネルギーを消費する |
| 敵が防御中→準備する | 無理に攻撃せず次の手を強める | 行動が1手遅れる |
| 安全で宝箱がある→宝箱へ | 余裕があるときに報酬を取る | その条件を教えるための枠が必要になる |

初期状態で使える基本行動を持たせ、4枠すべてを埋めないと遊べない状態は避ける。ルールの組み替えも教育1回を使うが、出発前の演習は無報酬で何度でも確認できる。

探索中は「見えている情報」「適用された教え」「実際の行動」を一緒に表示する。AIだけが未発見の罠や未来の部屋を知っている実装にはしない。

戦闘は2Dの簡単なターン制で、敵の予告に対して攻撃、防御、準備、回復を選ぶ。長引かせて資源を増やせないよう、戦闘ごとに最大ラウンド数を設け、時間切れはその探索から撤退する。上限は試作で決める。

## 6. 迷宮の生成とAIの役割

最小試作では、役割が明確な部屋を組み合わせる手続き生成を使う。乱数シードを記録して同じ迷宮を再現できるようにする。固定シードで教育の効果を比較し、別シードで同じ方針がどこまで通用するか試せる。

生成時に次の条件を確認する。

- スタートから出口または守護者まで経路がある。
- 進行は8段階以内で、報酬を無限回収できる循環がない。
- 回復・戦闘・罠・報酬の出現数が設定範囲に収まる。
- 序盤に必須資源のない強制イベントを置かない。

LLMを採用する場合の用途は、迷宮のテーマ、部屋の短い説明、探索日誌の表現を提案することから検証する。モデルが部屋構成を提案する拡張も考えられるが、使用可能な部屋IDと接続条件に制限し、検証に失敗した場合は既存の生成処理へ戻す。

初期版の遊べる地形と難易度は手続き生成が保証する。LLMを使わない場合、ストアでは「毎回構成が変わる迷宮」と説明し、生成AIが地形を作る機能があるようには扱わない。

自由なプロンプトで判断ルールを教える機能は将来候補。導入するなら、文章を4枠のルールへ変換した結果をプレイヤーが確認・修正できる形にする。実行時の行動判断は構造化されたルールで処理し、モデルの応答待ちを探索の必須要件にしない。

## 7. 周回と成長の上限

教育9回、探索3回、ルール4枠、装備2枠で育成を制限する。回復できる場所を周回して能力や資源を増やす構造は作らない。

周回で引き継ぐのは、教えの候補、初期性格、迷宮テーマ、卒業記録。能力値、持ち帰った素材、装備はリセットする。

再プレイでは、同じ迷宮を別方針で攻略する、介入を減らして自律探索を成功させる、苦手な迷宮に対応することを目標にする。自律攻略は任意の挑戦であり、初回から介入を罰する設計にはしない。

## 8. 最小試作と発売候補の範囲

| 項目 | 最小試作 | 検証後の発売候補 |
| --- | --- | --- |
| 進行 | 教育3回＋探索1回 | 教育9回＋探索3回の1周 |
| 初期性格 | 2種 | 3種 |
| 判断ルール候補 | 6種、装備4枠 | 12種、装備4枠 |
| 迷宮 | 1テーマ、固定シードと生成処理 | 3テーマ、各探索8段階 |
| 部屋テンプレート | 6種 | 12種 |
| 敵 | 通常2種＋守護者1種 | 通常6種＋守護者3種 |
| 装備 | 2種、装備2枠 | 6種、装備2枠 |
| 画面 | 教室、演習、探索、行動記録 | 左記にタイトル、説明、セーブ、卒業アルバムを追加 |

地形はノードと経路で表現し、自由移動や3Dの迷宮は作らない。パーティー編成、広い装備ツリー、オンライン要素、無限階層、完全自由な指示文は対象外。発売候補の数量は、試作結果と制作工数から調整する。

探索には一時停止と速度変更を設け、結果だけ飛ばした場合も重要な判断を行動記録から確認できるようにする。

## 9. 技術方針と品質確認

Godot等の2Dエンジンを候補にし、迷宮生成、判断ルール、戦闘、表示を分離する。部屋やルールはデータとして定義する。行動記録にはその時点の観測情報、適用ルール、選択行動、結果を残し、後から理由を再現できるようにする。採用エンジンは未決定。

確認対象は、迷宮の到達可能性、経路の有限性、ルール競合時の優先順位、実行不能な行動からの復帰、同じシードと入力による再現性、保存後の残り回数と資源の一致。自動チェックで生成条件を確認した後に、人のプレイで分岐の意味を評価する。

## 10. 収益と販売の仮説

定価1,280円、平均受取率60%、月の運営費2,000円という共通仮定では、月16本で月次運営利益10,288円。開発人件費・初期費用回収を含まない試算である。[共通の利益定義と計算](README.md#月1万円の利益に向けた共通試算)を参照。

見せたい映像は「宝箱に夢中で失敗→回復を教える→同じ危険を自力で突破」の比較。体験版では1回の探索と教え直しを体験させる。外見の違う迷宮を大量に見せるより、教えを変えると同じ場面の結果が変わることを訴求する。

近い自動化・探索・戦術ゲームを調査し、手順を組む遊びを好む人と、難しそうに感じる人を分けて反応を確認する。売れる前提で大量の部屋を制作しない。販売見込みは未算定。

## 11. 検証計画と判断基準

最初に固定の迷宮と数個のルールを紙で再現する。最小試作では固定シードで教え直しの効果を確認し、その後に別シードへ広げる。想定プレイヤー5人程度で観察する。

| 仮説 | 観察すること | 次段階へ進む仮基準 |
| --- | --- | --- |
| AIの判断を理解できる | 重要な分岐で、なぜその行動を選んだか説明できるか | 5人中4人以上が記録から説明できる |
| 教え直しが攻略になる | 失敗記録を見て1つの教えを変え、同じ場面の結果を改善できるか | 5人中3人以上が助言なしで改善する |
| 自律探索を見ていたくなる | 別のシードでも自発的に再挑戦するか | 5人中3人以上が再挑戦を選ぶ |

この人数と基準は早期の観察用で、統計的な販売予測ではない。ルールの編集を面倒と感じる場合は、条件の種類を減らし、具体例から教える方式を改善する。速度変更を入れても探索が退屈な場合は、部屋数の追加より判断が変わる分岐を増やすことを優先する。

## 12. 主なリスクと次の成果物

| リスク | 対応方針 |
| --- | --- |
| 教育がプログラミング作業に見える | 条件文を直接書かせず、状況の絵と行動候補で教える |
| AIが理不尽に見える | 見えている情報と適用ルールを表示し、無報酬の演習で予測を確かめられるようにする |
| ランダム生成が敗因を隠す | 固定シードで比較し、生成時の条件検証を行う |
| 見ている時間が長い | 停止・速度変更・判断場面への移動を用意する |
| 多数の仕組みが必要になり完成が遠のく | ノード型の迷宮、単体AI、少数のルールに絞る |

次に作るのは「判断ルール6種の一覧」「8段階の迷宮1本」「失敗から教え直すプレイ例」。これらで教育の楽しさを確認してから、生成する迷宮の種類を増やす。
