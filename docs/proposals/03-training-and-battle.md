# 企画書C：AI育成ラボ：卒業リーグ（仮）

作成日：2026-10-23／状態：企画初稿・未検証

[3案の比較と共通方針](README.md)

## 1. 企画の要約

プレイヤーは小さな研究所でAIの相棒を育てる。訓練、休息、模擬戦、試合後の指導で能力と行動の癖を伸ばし、24週目の卒業リーグ優勝を目指す。育成と大会を繰り返す楽しさを軸に、AIへの教育が自律的な戦い方として表れるゲーム。

**訴求文：強さも、戦い方も、あなたの育て方で変わる。**

| 項目 | 仮の方針 |
| --- | --- |
| ジャンル | AI育成シミュレーション・半自動対戦 |
| 販売先・対象環境 | Steam／Windows PC／日本語 |
| 1周の長さ | 60〜90分 |
| 育成期限 | 24週で卒業。8・16・24週は公式戦 |
| 価格案 | 買い切り1,480円。購入意向と完成度を見て再検討 |
| 通信 | 基本プレイはオフライン完結 |
| 最優先の面白さ | 相棒に愛着を持ち、育てた能力と行動の癖で強敵を突破すること |

「モンスターファーム」のような、育成→大会→育成という循環を参照する。世界観はAI研究所、教育の中心は状況に応じた行動の学習とし、キャラクターや技、画面、数式は独自に設計する。

想定するプレイヤーは、育成シミュレーション、相棒への愛着、限られた期間の計画、対戦相手への対策が好きな人。素早い操作や格闘ゲームの入力技術は要求しない。

## 2. プレイヤー体験

最初は怖がって後退ばかりするAIが、模擬戦で「相手の大技の後なら反撃してよい」と教えられ、公式戦でその通り動く。逆に、攻撃を褒め続けたAIは攻めが鋭くなる一方、危ない場面でも前に出る。

能力を伸ばすだけでなく、「この相棒はどんな場面で何をしがちか」を理解して育てることが攻略になる。弱点を消すのか、長所を尖らせて補うのかを選べるようにする。

短いプレイ例：

1. 次の相手は、近距離で強いが大技の後に隙ができる。
2. 精度を伸ばす訓練と、遠距離で待つ模擬戦を選ぶ。
3. 試合でAIが距離を保ち、相手の大技の後だけ踏み込む。
4. 育成記録に、過去の指導が今回の選択へ影響したことが残る。

## 3. 基本ループと勝敗

`AIを迎える → 週ごとに育成 → 8週目の公式戦 → 育成 → 16週目の公式戦 → 育成 → 24週目の卒業リーグ → 卒業アルバム`

- 24週のうち3週は公式戦に使うため、自由に選べる育成行動は21回。
- 通常週は訓練、模擬戦、休息のいずれか1つを選ぶ。週を戻して成果だけ積み上げることはできない。
- 8・16週目の結果にかかわらず育成を続けられる。勝利報酬は技や訓練の選択肢を中心にし、敗北後にも対策の道を残す。
- 24週目は1試合の卒業決勝として始める。勝てば優勝、敗北または引き分けでも卒業し、その周を終了する。
- 次の公式戦の相手と得意戦術は前の公式戦後に公開する。初戦の相手は育成開始時に公開する。

寿命や期限を延長して際限なく育てる仕組みは設けない。卒業したAIは記録として残り、育成や報酬を得る試合には再投入しない。

## 4. 能力、疲労、技の育成

| 要素 | 遊びでの役割 |
| --- | --- |
| 出力 | 技で与えるダメージを伸ばす |
| 精度 | 技の有効条件や弱点を突く効果を強める |
| 機動 | 間合いの調整と行動順に関わる |
| 耐久 | 体力と防御面を伸ばす |
| 疲労 | 訓練効率と試合時の能力に影響する。休息が必要になる |
| 性格 | 初期の行動傾向と育成の得手不得手を決める |
| 技 | 装備は4枠。間合い、消費エネルギー、準備条件を持つ |

能力と疲労の範囲は初期仕様では0〜100。重い訓練は能力を大きく伸ばすが疲労を増やす。休息にも1週を使うため、訓練回数、体調、試合対策の配分が必要になる。

選択前に予想される成長と疲労変化を表示する。試作ではランダムな大失敗を使わず、育成計画と結果の関係を分かりやすくする。

技を多数覚えても装備枠は増やさない。回復や稼ぎを繰り返して週を消費せず強化する方法は用意しない。

## 5. AIを教育する仕組み

教育は、模擬戦や公式戦の重要な行動に対して「よかった」「次は別の方法」を選ぶことで行う。指導はその週の行動の一部とし、1行動につき評価できる場面は1つ。戦闘を放置して大量に学習点を稼ぐ方式にはしない。

| 行動傾向の例 | 教えた結果 | 偏った場合の弱点 |
| --- | --- | --- |
| 安全なときに接近する | 得意な近距離技を狙う | 相手の誘いにも近づきやすい |
| 相手の準備中は警戒する | 大技に備えて防御や後退を選ぶ | 準備のふりで攻めを止められる |
| 相手の隙に反撃する | 準備後や消耗時を狙う | 相手が隙を見せないと消極的になる |
| エネルギーを温存する | 強い技を使う機会を待つ | 使い切る前に試合が終わることがある |
| 不利なときに距離を取る | 体勢を立て直す | 時間切れの判定で不利になりやすい |
| 有利なときに攻め切る | 決着を早める | 反撃を受ける危険が増える |

行動傾向は6項目に絞り、各傾向の重みは例えば−3〜＋3の有限範囲で管理する。更新される値を指導前後に表示する。ルールを直接並べる探索案と異なり、この案では性格と過去の教育から戦い方の傾向を作る。

行動は「初期性格による点＋教育による点＋現在の状況による点」で候補を比較して選ぶ。最小試作はこの仕組みを使い、実際のニューラルネットワーク再学習は行わない。

## 6. バトルの仕組み

1対1、近距離・中距離・遠距離の3段階の間合いを使う。1試合は最大10ラウンド、2〜3分を仮目標とする。各ラウンドで双方が移動、技、防御、エネルギー回復から1つを選び、定めた順序で解決する。

- AIは装備技、性格、教育された傾向から自動で行動を選ぶ。
- プレイヤーは1試合2回まで、表示された実行可能な行動へ切り替える指示を出せる。指示を無視する確率判定は設けず、何が操作できるかを明確にする。
- 行動前に選択理由を短く表示する。重要場面は停止して確認でき、通常場面は早送りできる。
- 相手の体力を0にすれば勝利。10ラウンド終了時は残り体力の割合で判定し、同値は引き分けとする。
- 間合いが合わない技は使えず、強い技には消費や準備条件を設ける。距離、資源、タイミングの選択で勝敗を作る。

最小試作では命中率による乱数を省き、間合いと準備条件によって命中・効果を決める。能力差だけで同じ行動を繰り返すのが最善にならないかを重点的に調べる。

## 7. プロンプトとローカルLLMの役割

最小試作では、AIを迎えるときに素体と初期性格を選ぶ。名前は自由入力、能力総量は同条件にそろえ、強い個体が出るまで生成し続けることを必須にしない。

プロンプトからのキャラクター作成は発売前の検証候補とする。導入するなら、短い文章を外見の部品、初期性格、得意分野のタグへ変換し、生成結果を確認して修正できるようにする。能力は固定の総量予算内で配分し、文章の長さや強そうな表現で無制限に上がらないようにする。

ローカルLLMを使ったキャラクター作成も拡張候補。ただし、異なるモデルの出力をゲームの性格タグへ変換する必要があり、モデルの性能をキャラクターの強さへ直接対応させる仕様にはしない。配布容量、必要メモリ、生成待ち時間、利用条件、対応環境を確認してから採否を決める。

LLMを使わない構成でも、名前、性格、行動傾向、色や部品の組み合わせで個体差を作れる。通常の育成と戦闘はローカルのゲーム処理で完結させ、外部APIやモデルの導入を購入後の必須作業にしない。

## 8. 卒業、引き継ぎ、愛着

24週で必ず卒業し、能力と技の装備状態は次世代へ加算しない。解放されるのは素体、初期性格、技の候補、研究所の見た目など、遊び方の幅を増やす要素にする。

卒業アルバムには名前、得意技、行動傾向、公式戦の成績、印象的な指導を残す。引き継ぎを設ける場合は、既存の初期選択肢と交換する性格タグ1つまでとし、世代ごとに能力が積み上がる方式にしない。

再プレイの目標は、別の素体での優勝、前回と違う間合いの攻略、苦手な性格を活かす育成、全ての公式戦を勝ち抜くことに置く。

## 9. 最小試作と発売候補の範囲

| 項目 | 最小試作 | 検証後の発売候補 |
| --- | --- | --- |
| 進行 | 8週：育成7回＋公式戦1回 | 24週：育成21回＋公式戦3回 |
| 素体 | 1種 | 3種 |
| 初期性格 | 2種 | 3種 |
| 通常週の選択肢 | 訓練2種、模擬戦、休息 | 訓練4種、模擬戦、休息 |
| 技 | 4種、装備4枠 | 12種、装備4枠 |
| 行動傾向 | 3項目 | 6項目 |
| 相手 | 1体 | 6体から1周3体を選出 |
| 画面 | 研究所、育成、作戦、試合、結果 | 左記にタイトル、説明、セーブ、卒業アルバムを追加 |

発売候補の数量は仮の上限。交配システム、大量の種族、自由な3D移動、リアルタイムのアクション操作、オンライン対戦、モデル学習環境は対象外。

表情や短い反応で性格を見せ、技の数に比例して大量の固有アニメーションが必要になる構成を避ける。一方、間合い、攻撃、防御、被弾は見分けられる必要がある。

## 10. 技術方針と品質確認

Godot等の2Dエンジンを候補にし、育成カレンダー、能力更新、行動傾向、戦闘、記録表示を分離する。技、教育、相手をデータとして定義し、同じ状態からの試合を再現できるようにする。採用エンジンは未決定。

確認対象は、24週で必ず終了すること、1週に複数回成長しないこと、行動傾向の上限、技の使用条件、判定勝敗、保存後の週数・能力・記録の一致。能力をそろえて行動傾向だけを変える試合と、逆に能力だけを変える試合で、それぞれの影響を確かめる。

## 11. 収益と販売の仮説

定価1,480円、平均受取率60%、月の運営費2,000円という共通仮定では、月14本で月次運営利益10,432円。開発人件費・初期費用回収を含まない試算である。[共通の利益定義と計算](README.md#月1万円の利益に向けた共通試算)を参照。

見せたい映像は「弱気で逃げるAI→模擬戦で教える→公式戦で狙い通り反撃する」の成長。体験版は最初の8週で、育成、教育、公式戦、振り返りまで完結させる。

育成ゲームとしての分かりやすさは期待できるが、購入意向は未検証。既存の育成ゲームのレビューから、愛着、作業感、育成期限、戦闘への関与に対する評価を調べ、自作品の差別化を確かめる。高めの価格案を正当化するためだけに種族や技を増やさない。

## 12. 検証計画と判断基準

最初に表で8週分の育成と1試合を再現する。最小試作では能力の成長と行動の教育を区別して見せ、想定プレイヤー5人程度で観察する。

| 仮説 | 観察すること | 次段階へ進む仮基準 |
| --- | --- | --- |
| 教育が戦い方に表れる | 指導によって変わった行動を説明できるか | 5人中4人以上が具体例を1つ説明できる |
| 育成計画に選択がある | 相手を見て訓練、模擬戦、休息の配分を変えるか | 5人中3人以上が自分で対策を立てる |
| 相棒への愛着と再挑戦が生まれる | 自分のAIの特徴を語り、別の育て方を試したがるか | 5人中3人以上が特徴と次の育成案を自分の言葉で述べる |

この人数と基準は早期の観察用で、統計的な販売予測ではない。行動の教育が理解されず能力だけを上げる遊びになる場合は、学習する状況を減らして結果表示を改善する。大会前の週が作業になる場合は、週数や選択肢を増やさず、次の相手への対策が必要かを見直す。

## 13. 主なリスクと次の成果物

| リスク | 対応方針 |
| --- | --- |
| 既存の育成ゲームとの差が弱い | 試合後の教育で行動が変わる場面を核心にする |
| AIが思い通りに動かず不満になる | 候補行動と理由を表示し、限定した指示を確実に使えるようにする |
| 育成が同じボタンの繰り返しになる | 相手の戦術、疲労、装備枠で計画を変える理由を作る |
| 卒業が喪失感だけを生む | 名前、戦績、教育履歴を残し、終了までの期限を最初から示す |
| 技や種族を増やして制作が膨らむ | 素体3種・技12種を仮上限にし、完成見本で工数を計測する |

次に作るのは「8週の育成表」「技4種と相手1体の仕様」「同じ能力で教育だけが違う2体の対戦例」。教育された癖が遊びになるかを確かめてから、長い育成期間とキャラクター数へ展開する。
