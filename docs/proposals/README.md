# AI育成ゲーム 企画案比較

作成日：2026-10-23／状態：企画初稿・採用案未決定

Steamで販売する小規模なAI育成ゲームについて、3つの独立した案を比較する。3案をまとめて実装する計画ではない。プレイテストと市場確認を経て、まず1案を選ぶ。

## 企画書

| 案 | 企画書 | プレイヤーの中心的な楽しみ |
| --- | --- | --- |
| A：討論大会 | [ことばの弟子](01-debate-tournament.md) | 自分の教えた価値観や話し方で、異なる審査基準の相手に勝つ |
| B：ダンジョン探索 | [迷宮の教え子](02-dungeon-exploration.md) | AIに判断ルールを教え、探索結果から教育を改善する |
| C：育成×バトル | [AI育成ラボ：卒業リーグ](03-training-and-battle.md) | 個性のあるAIへの愛着と、能力・行動の癖を育てる攻略を両立する |

## 共通の前提

- 目的はSteamで販売し、月1万円の利益を生む作品を作ること。
- 個人または少人数の開発を仮定する。人数・予算・開発可能時間は未確定。
- 初期対象はWindows PC、日本語、買い切り、1人用。オフラインで基本プレイを完結させる。
- 育成には終了期限を設ける。恒久的な能力加算で周回するほど際限なく強くなる設計は採らない。
- グラフィックの物量より、育成の選択と結果のつながりを優先する。ただし、状況の読みやすさ、操作の分かりやすさ、結果の演出は必要なゲーム品質として扱う。
- AIを教育する遊びと、生成AIモデルを動かす実装は分けて検討する。最小試作では、教育に応じて変わるルールや重みを使い、LLMなしで面白さを検証する。
- 現在のリポジトリにはアプリの実装がない。本書の機能・価格・数量・評価基準はすべて企画上の仮説であり、完成済み機能や市場調査結果ではない。

## 選定のための比較

| 比較項目 | A：討論大会 | B：ダンジョン探索 | C：育成×バトル |
| --- | --- | --- | --- |
| 教育の対象 | 価値観、会話技、話し方 | 条件付きの判断ルールと優先順位 | 能力、技、状況ごとの行動傾向 |
| 基本ループ | 教育4回→討論を3巡 | 教育3回→探索を3巡 | 24週の育成、8・16・24週に公式戦 |
| 1周の想定 | 30〜45分 | 45〜60分 | 60〜90分 |
| 育成の上限 | 教育12回、装備技4枠 | 教育9回、判断ルール4枠、探索3回 | 24週で卒業、装備技4枠、行動傾向6項目 |
| バトル中の関与 | 事前作戦＋1試合2回の助言 | 経路・戦闘を観察＋探索中2回の介入 | 半自動戦闘＋1試合2回の指示 |
| 主な制作負荷 | 短い会話、採点の分かりやすさ | 地形生成、条件判定、経路と戦闘の整合性 | 育成バランス、対戦AI、戦闘演出 |
| 最大のリスク | 勝敗が恣意的に見える、文章が長い | 教育がプログラミング作業に見える | 数値上げが単調、観戦が退屈になる |
| 最小試作の終了地点 | 4回育成後の1試合 | 3回教育後の1回の探索 | 最初の8週と1試合 |
| 訴求したい瞬間 | 教えた口癖が勝敗を変える | 以前の失敗を教え直して突破する | 怖がりだったAIが教え通り反撃する |

難易度や売れやすさの順位は未検証。Aは画面と素材を絞りやすい一方、討論の納得感を成立させる設計が難しい。Cは育成と試合の説明がしやすい一方、既存の育成ゲームと比べられる。Bは教育と自律行動の結びつきが強い一方、実装する仕組みが多い。

最初の試作候補はAとする。理由は「教育の結果が勝敗につながるか」を比較的小さな画面構成で検証できるため。自由な会話よりキャラクターへの愛着を重視したくなった場合はC、行動ルールの工夫そのものが楽しいと分かった場合はBを優先する。この推奨は採用決定ではない。

## 月1万円の利益に向けた共通試算

まず継続性を測る指標として、月の受取額から月の運営費を引いた「月次運営利益」を仮置きする。開発人件費・初期費用の回収・所得への課税を含む事業全体の利益は別途評価する。ユーザーの利益目標の定義として確定したものではない。

以下は価格の比較用シナリオ。定価に対する平均受取率60%は、値引き、販売地域、ストア側控除、返金等をまとめた便宜的な仮定であり、Steamの公式手数料率を示すものではない。月の運営費2,000円も予算枠としての仮定で、オフラインゲームに必ずこの費用が生じるわけではない。

`必要月間販売本数 = ceil((目標利益10,000円 + 月運営費2,000円) / 1本あたり平均受取額)`

| 案 | 仮の定価 | 平均受取額：定価×60% | 目標に必要な月間本数 | その本数での月次運営利益 |
| --- | ---: | ---: | ---: | ---: |
| A | 980円 | 588円 | 21本 | 10,348円 |
| B | 1,280円 | 768円 | 16本 | 10,288円 |
| C | 1,480円 | 888円 | 14本 | 10,432円 |

高い価格ほど少ない販売本数で済むという算数は、購入されやすさを保証しない。実際の価格は競合作品、製品の完成度、体験版の反応から再検討する。

例として初期費用60,000円を12か月で回収する場合、月5,000円の回収分を追加する。必要本数はAが29本、Bが23本、Cが20本になる。これは初期費用の見積もりではなく感度分析の例であり、開発人件費の回収はまだ含まない。

制作中は実働時間も記録し、初期費用、販売開始に必要な費用、素材・音源費と合わせて採算表を更新する。発売月の売上だけで判断せず、発売後の複数月について、実受取額、費用、販売本数を確認する。

## 開発の進め方

| 段階 | 実施すること | 次へ進むために確認すること |
| --- | --- | --- |
| 1. 机上検証 | 候補ごとに近いSteam作品3〜5本を調べ、価格、説明、レビューの不満、見せ方を記録。紙や表で育成と1試合を再現 | 誰が買うのか、自作品の違い、破綻しそうなルールを説明できる |
| 2. 最小試作 | 第一候補の核心だけを仮素材で実装。UI中心の2Dを想定し、Godot等の候補エンジンで保存・入力・PC出力を小さく確認 | 育成の選択が結果を変え、その理由が分かる |
| 3. 外部プレイテスト | 想定する購入者に近い5人程度で観察。各企画書の仮基準を使う | 手伝わなくても遊べ、次の育て方を自分で考える人がいる |
| 4. 短い完成見本 | 1区間だけ画面、音、説明、セーブを製品相当に仕上げ、制作時間を測る | 残りの量と工数を見積もれる。ストアで見せたい場面がある |
| 5. 範囲の確定 | 発売範囲と後回しの機能を固定。見本の実績から予算・予定を組み直す | 手持ちの開発時間と費用で完成できる |
| 6. 体験版と販売準備 | 代表的な遊びを体験版にし、ストアの説明や映像で約束する内容と合わせる | 面白さの伝わり方、離脱理由、購入意向を確認できる |
| 7. 発売と改善 | 不具合修正を優先し、レビュー、返金理由、月次収益を確認する | 追加機能の前に、購入者が期待した体験を提供できている |

最初から3案の実装を並行して進めない。第一候補の主要仮説が崩れ、短い修正でも改善しない場合に次案へ移る。外部テストの合格は販売成功の証明ではない。

## 今は確定しないこと

- 発売日、最終価格、売上予測、完成までの総工数。
- LLMの採用、モデル、API提供元、自由入力の範囲。
- オンライン対戦、クラウド保存、追加販売、多言語対応。
- 作品の正式名称、キャラクターの最終デザイン、詳細な数値バランス。

検証した結果で変える事項を残しつつ、最小試作の範囲は各企画書で具体化する。
